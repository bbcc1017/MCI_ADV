# MCI_ADV 지도·라우팅·자원 데이터 개선

확인일: 2026-10-19. 로컬 앱의 기능·성능 검증 기록이며, 운영 서버의 배포 성공 여부는 검증 범위에 포함하지 않았다.

## 반영 결과

- 지도 안 오른쪽 위에 **도로지도 / 회색지도** 버튼을 배치했다. 확대·축소 바로 아래의 **위성** 버튼으로 위성지도와 직전에 선택한 일반 지도를 오간다. 지도 테마 선택은 페이지 전체를 다시 실행하지 않는다.
- 기존 Streamlit 화면에서 제목·상태·탐색 메뉴를 압축하고 지도 폭을 넓혔다. 지도 페이지의 중복 미니맵을 없애고, 프로젝트 경로는 로컬 고급 설정으로 접었다. 좁은 화면에서는 메뉴 아이콘을 줄여 다섯 메뉴를 한 줄로 표시한다.
- 선택한 경로에 맞춰 최초 지도 범위를 잡는다. 범례는 접을 수 있고, OSRM에는 실시간 혼잡도 범례를 붙이지 않는다. 타일 출처도 읽을 수 있는 크기로 표시한다.
- OSRM은 안전센터→현장, 현장→병원의 거리·시간을 **최대 40구간씩 table**로 조회한다. Kakao의 API·스냅·폴백·호출 순서와 기본 파라미터는 유지했다.
- table 원본은 `routes/tables/`에 보존하며, 각 구간 JSON에는 원본 응답 파일과 행·열 위치를 기록한다. CSV의 거리 km·시간 분, 시뮬레이션 입력 형식은 같다. table 미지원·오류·도달 불가 셀은 기존 route 계산으로 재시도하며, 실패를 거리 0으로 대체하지 않는다.
- 경로선은 지도 표시 시 필요한 구간만 받아 1시간 캐시한다. 첫 조회는 최대 4개씩 병렬 처리한다. 저장된 예전 OSRM/Kakao 경로 JSON도 계속 읽는다. 새 table 경로선을 받지 못하면 정적 지도에 안내하고 애니메이션을 중단한다.
- 애니메이션의 병원 경로를 API 호출 순서 대신 시뮬레이션 병원 인덱스와 이름·좌표로 연결했다. 이미 차량 수만큼 전개된 구급차를 다시 보유대수만큼 중복 전개하던 연결도 수정했다.

Streamlit을 유지하면서 지도 제어를 Leaflet 안으로 옮겼다. 이번에 확인한 주요 지연은 개별 라우팅 요청과 경로선 조회였다. 전체 프론트엔드를 다른 프레임워크로 교체하지 않고 해당 지연과 화면 구성을 개선했다. 시뮬레이션 코어는 수정하지 않았다.

## 성능 측정

측정은 로컬 Python 3.12 / Streamlit 1.55 / 공식 공개 OSRM 서버에서 수행했다. 다음 수치는 초기 검증 시점의 단일 실측이며, 전체 앱의 일정한 속도 배수를 뜻하지 않는다. 푸시 전 최신 자료 통합 후 자동 테스트와 시나리오 생성·시뮬레이션 회귀 검증을 다시 수행했다.
